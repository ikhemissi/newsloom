## Local checks

Install the locked tools as shown in the [README](../README.md), then run:

```bash
bash scripts/check.sh
```

The [check script](../scripts/check.sh) implements the
[OpenSpec quality gates](../openspec/specs/repository-foundation/spec.md#requirement-cloud-credential-free-quality-gates),
plus dependency-lock checks and mocked-provider Terraform tests.
[GitHub Actions](../.github/workflows/checks.yml) invokes the same script; no
automatic deployment workflow exists yet.

The identifier guard checks tracked and untracked non-ignored files, including a
repository with no commits. It is a narrow guard, not a replacement for secret
scanning. Store actual deployment values in ignored local environment configuration.

Optional focused commands:

```bash
uv run ruff check .
uv run ruff format .
uv run mypy
uv run pytest --cov --cov-report=term-missing
uv build --all-packages
uv run pre-commit validate-config
```

See [P1-C11](prd-1-capabilities.md#p1-c11-evidence-based-platform-acceptance) for
database-test requirements. Bootstrap needs no Docker daemon. Add integration
dependencies when their owning capability is implemented. The platform's
[database tests](azure-platform.md#local-database-tests) use an explicitly started
PostgreSQL 18/pgvector instance; CI provides that disposable service.

## OpenSpec

OpenSpec is pinned in [package.json](../package.json) and its lockfile.
Use `npx openspec` to use that version rather than a different global installation.
GitHub Copilot skills and prompts were generated by `openspec init`. Reload VS Code
if its new `/opsx-*` commands are not visible.

```bash
npx openspec list
npx openspec status --change "<change-name>"
npx openspec validate --all --strict --no-interactive
```

### Choose a delivery track

Defined by the [delivery contract](../openspec/specs/repository-foundation/spec.md#requirement-lightweight-delivery-track):

| Track | Use for | Steps |
| --- | --- | --- |
| Lightweight | Tuning, prompts, ranking, bug fixes, docs, operational commands within existing contracts | Edit, test locally, commit with a descriptive message, update the owning runbook, deploy if behavior changed |
| OpenSpec | New capability, cloud resource, identity, permission, dependency or data contract | `npx openspec new change <name>` (or `/opsx-propose`), implement, check, deploy, archive |

For OpenSpec changes, record verification outcomes in the change's tasks. When
the only remaining checks cannot run (for example a signed-in regular-browser
journey), record them in [known gaps](known-gaps.md) and archive the change with
`npx openspec archive <change-name> --yes`; do not mark them passed.

### Checks and deployment

`bash scripts/check.sh` always runs lint, types, service startup, config and spec
checks (about 20 s), then only the suites affected by files changed since
`origin/main` (committed, staged or new). [`scripts/check_plan.py`](../scripts/check_plan.py)
derives that from imports: a test runs when it, a helper it imports, a service it
imports, or a shared core module those use changed. Dependency manifests, CI and
check tooling, or any unrecognised path select everything. Terraform runs per
changed layer; the evaluation tooling suite runs when its tool or the pinned
manifests change; browser journeys run for web and web-contract changes.

| Command | When |
| --- | --- |
| `bash scripts/check.sh` | Local work; draft PRs in CI |
| `bash scripts/check.sh --all` | Everything, including slow privacy tests; ready PRs and `main` in CI |
| `bash scripts/check.sh --reuse` | azd hooks: skip when this exact source already passed |
| `bash scripts/eval.sh [--live]` | Offline evals: recorded replays ($0); `--live` adds real model evals (a few cents). CI runs them on ready PRs and `main` |

Database tests run serially (they share one database) alongside the rest; the
evaluation suite runs in parallel workers. Work on a branch with a draft PR; mark
it ready when you want the full check and evals. Use `azd env select dev` for the
existing environment; see the [state runbook](azure-bootstrap.md).

Iterate on model-driven behavior locally before deploying. For the briefing, see
the [preview workflow](briefing.md#local-preview).

## Feed catalogue

Edit [config/feeds.json](../config/feeds.json), then run
`uv run newsloom-validate-feeds config/feeds.json`. Validation rules belong to the
[OpenSpec catalogue contract](../openspec/specs/repository-foundation/spec.md#requirement-validated-initial-feed-catalogue).
This command validates configuration, not network safety or article content;
those contracts are [P1-C02](prd-1-capabilities.md#p1-c02-safe-feed-retrieval-and-normalization)
and [P1-C03](prd-1-capabilities.md#p1-c03-content-screening-and-quarantine).
