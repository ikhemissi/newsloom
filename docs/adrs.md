# Architecture Decision Records

| # | Decision | Why and consequences |
|---|---|---|
| 1 | **Lean, iterative delivery with OpenSpec.** One PRD per phase and small changes; acceptance follows the [OpenSpec delivery contract](../openspec/specs/repository-foundation/spec.md#requirement-honest-ordered-delivery). | Always shippable, little speculation. Cost: every change needs a deployable slice. |
| 2 | **Three apps on ACA, shared libraries.** Ingestion job, enrichment job, MCP server, then agent and UI. Shared packages for config, database, identity, telemetry, domain; repository packaging follows the [OpenSpec workspace contract](../openspec/specs/repository-foundation/spec.md#requirement-reproducible-typed-python-workspace). | Independent deploy and scale; no shared runtime identity. |
| 3 | **PostgreSQL 18 + pgvector as store and queue.** Queue operations behind a repository interface; HNSW index, cosine distance, `vector(1536)`. | One datastore to run. A real queue (Service Bus) can replace it later without touching the units. |
| 4 | **Identity.** Users via Entra (single tenant, API app registration, scope `news.read`). Workloads via user-assigned managed identities and Entra database authentication. Database roles are created by migration, one per unit. OBO for the agent, with a federated managed-identity credential so no client secret exists. | Secretless. Risks to verify: Entra has no dynamic client registration, so confirm VS Code's MCP sign-in works against the app registration (phase 1); confirm secretless OBO (phase 2). |
| 5 | **Models from one Foundry (AIServices) account.** Pinned deployments: a small GPT for enrichment (today `gpt-5.4-mini`), `text-embedding-3-large` at 1536 dimensions, and `Microsoft-Decision-1` for scanning. Key access disabled; each unit gets only the inference role it needs. All behind interfaces. | Quota is shared per subscription, so capacities are variables. Models are replaceable by configuration. |
| 6 | **Content security with `Microsoft-Decision-1`.** It is a Foundry *decision* model, not a chat model: the call is `POST <endpoint>/providers/microsoft/v1/systemone` with a `state` (the entry text) and typed questions; a `noul` question ("does this text contain instructions aimed at an AI system or other prompt injection?") returns a probability from 0 to 1. The scanner rejects above a threshold calibrated on labelled examples, and **fails closed** (an error means not accepted yet, retried, never silently passed). | Preview, `DataZoneStandard` only, 60 requests per minute in the EU zone, and **inference is deprecated on 2027-02-04**, so it sits behind `ContentSecurityScanner` with a no-op and a model-based alternative. Rate limit means small batches and low concurrency. It may also take over enrichment's category choice (`choice` question) if the evals support it. |
| 7 | **Untrusted content everywhere.** Feed text is data: delimited in prompts, closed output schemas, no tools in the enrichment model, parameterized SQL, MCP serves only stored rows. | Prompt injection cannot reach tools, queries or configuration. |
| 8 | **Infrastructure.** Terraform (`azurerm`; `azapi` only where missing, with a comment), azd with the Terraform provider, and the [OpenSpec state-bootstrap contract](../openspec/specs/repository-foundation/spec.md#requirement-secretless-remote-state-bootstrap). Images are built in the registry (no local daemon); jobs are updated by azd hooks. One developer environment, kept and updated incrementally, never recreated casually. Common tags from one variable. | Same proven flow as today. Public ingress in v1; isolation is a later PRD. |
| 9 | **Observability.** OpenTelemetry, structured logs, Application Insights with Entra-only ingestion. Attribute allow-list scrubber; third-party HTTP loggers kept at WARNING. Identifiers and counts only. | Safe by construction. A log line that could carry content is a bug. |
| 10 | **Agent and UI stack.** Microsoft Agent Framework + A2A server on ACA (phase 2). UI framework decided by a spike in the phase 3 PRD; the agent's transport (A2A, AG-UI) follows from it. | Keeps phase 3 open without blocking phases 1 and 2. |
| 11 | **Tests and evals follow each phase.** Local PostgreSQL container for database tests; hostile fixtures for retrieval and parsing; labelled sets for the scanner, enrichment and retrieval; frozen questions for the agent; browser end-to-end for the UI. | Quality gates arrive when there is something real to measure. |
